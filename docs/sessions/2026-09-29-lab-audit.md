## Phase A2 — the four recorded issues

**All four are still present. Two are worse than recorded.**

### (a) Dashboard interval toggle — CONFIRMED, and unconditional

`frontend/pages/04_Dashboard.py:710`

```python
fillcolor=f"rgba({int(color[1:3],16)},{int(color[3:5],16)},{int(color[5:7],16)},0.15)",
```

This slices `color` as if it were `#RRGGBB`. The palette is
`px.colors.qualitative.Set2` (line 680), and **every one of its eight entries is
an `rgb()` string**:

```
['rgb(102,194,165)', 'rgb(252,141,98)', 'rgb(141,160,203)', ...]
```

So `color[1:3]` is `'gb'` and the call raises:

```
ValueError: invalid literal for int() with base 16: 'gb'
```

**Recorded as conditional ("when a palette colour is an rgb() string"). It is
not conditional — it fires every time.** The guard at line 701 is
`if show_pi and has_pi and len(models_sel) == 1`, so the crash needs the interval
toggle on, interval data present and one model selected; given those, it always
crashes.

### (b) Compare page `KeyError 'MAE'` — CONFIRMED, and live

`frontend/pages/05_Compare.py:204`

```python
if "model" in m.columns:
    best_row = m.loc[m["MAE"].idxmin()]
```

The guard tests for `model` and then indexes `MAE`, which it never checked. The
inconsistency is local: line 209 uses `if metric in best_row.index` and line 222
uses `if c in mdf.columns`. Line 204 is the one unguarded access.

**This is live, not theoretical.** Despite the filename, most
`metrics_long.csv` files are *wide* (`MAE` is a column). But the E_QUANTILE
family writes a genuinely long one:

```
model,fold,metric,quantile,value
```

It has `model` and no `MAE`. Of 64 `metrics_long.csv` files on this machine, 9
are long-format — every E_QUANTILE run. Replaying lines 195–204 against
`backend/forecast_runs/2026-08-12/e_quantile/metrics_long.csv` reproduces
`KeyError: 'MAE'`. The `target`/`horizon` filters above do not save it: those
columns are absent from the long format, so both filters are skipped and the
frame arrives at line 204 non-empty.

The second half of the recorded issue — a missing top-level `metrics_long.csv` —
**does not crash.** `load_run_outputs` returns `metr=None` and line 192
`continue`s. The table is silently empty instead.

### (c) Tri-state gate verdict — CONFIRMED on all three lines

`frontend/pages/07_Forecast.py:673`

```python
verdict = _translate("passed") if g.get("passed") else _translate("failed")
```

A binary read of a three-valued field. `passed=None` means *not tested*; this
renders it as **failed**.

All three recipes in `registry/recipes.json` carry
`dev_credentials.gates.coverage.passed = null`:

| Target | coverage `passed` | page renders |
| --- | --- | --- |
| Revenues | `None` | **failed** |
| Expenditure | `None` | **failed** |
| State budget balance | `None` | **failed** |

**The page contradicts itself.** Line 674 prints the reason directly beneath the
badge:

> This model reports no prediction intervals, so their calibration was not
> measured. Point forecasts are unaffected.

So the client reads "interval coverage: **failed**" above a caption saying the
calibration was never measured. This asserts a failure that was never tested, on
every target, and it is the most client-damaging of the four.

Confirmed on the official path too: `forward_gates.json`, written by the official

### (d) B_ML selection refusal — CONFIRMED, and it affects two families

`scripts/run_daily_forecast.sh:133` sets B_ML's overrides to:

```bash
overrides='{"folds":1,"min_train_years":4}'
```

No `eval_start`, no `eval_end`. With none, `build_yearly_folds` folds to the end
of the data, so evaluation rows land in TEST (2025-01-01 .. 2025-08-06). The
guard at `b_ml_pipeline.py:1092` then refuses, because selection is permitted
only on `{train, dev}` and DEV ends 2024-12-31.

`ConfigBML` accepts both `eval_start` and `eval_end` (`b_ml_pipeline.py:119-120`)
and `build_yearly_folds` honours them, so the bound the script needs already
exists — the script simply never passes one.

**Broader than recorded: E_QUANTILE fails the same way, for the opposite
reason.** Its override at line 140 is
`{"eval_start":"2025-01-01","min_train_years":4}` — an evaluation window aimed
deliberately *into* the sealed holdout. Selection therefore refuses too. One
family lacks a bound; the other has one pointing at TEST. Both abort.

## Phase A3 — the three parked findings, unchanged

Confirmed present. **Nothing was fixed.**

**1. `ops_monthly_baseline` all-NaN fallback** — `backend/b_ml_pipeline.py:278-281`

```python
m = series.resample("ME").sum().astype(float)
return m.groupby(m.index.month).transform(lambda x: x.shift(12).rolling(36, min_periods=1).mean())
```

`shift(12)` runs *inside* a per-calendar-month groupby, where each group holds one
entry per year. So it shifts **12 years**, not 12 months. On a 2015–2025 span
(11 entries per group) the result is **all NaN — 0 of 128 monthly points**.

**2. GBQuantile crossed intervals** — `backend/e_quantile_daily_pipeline.py:425`

```python
if model_name == "GBQuantile":
    return {q: _fit_gb_quantile(X_tr, y_tr, X_new, q) for q in quantiles}, 0
```

Each quantile is an independent fit, which cannot guarantee p10 ≤ p50 ≤ p90.
GBQuantile does **not** pass through `_enforce_monotone`, and the crossed count
is hardcoded `0`, so a crossed band is neither repaired nor reported. Newer
entries (LinearQuantile, HistGBQuantile, XGBQuantile) do route through it — Phase
B printed `XGBQuantile fold 27: repaired 1 crossed row(s) of 5`, proving crossing
is real rather than theoretical.

**This sits on the official path.** The Phase B forward run chose GBQuantile as
the interval model for all three targets. No crossing appeared in that
15-row output (0 of 15), so it stays a latent risk, not an observed failure.

**3. ResidualRF silent repair** — `backend/e_quantile_daily_pipeline.py:427`,
with the repair at `:574-576`

```python
for lo, hi in zip(sorted(quantiles), sorted(quantiles)[1:]):
    preds[hi] = np.maximum(preds[hi], preds[lo])
```

It repairs, then returns a hardcoded `0`. The module's own docstring names the
cost: "nobody learns when a model is crossing constantly, and constant crossing
is how a misconfigured quantile model looks from the outside."

# Fixes applied (2026-09-30)

Branch `fix/ui-rendering-and-script`, cut from `main` at `1f53b36`. Approved at the
gate: all of group (i) **except** the E_QUANTILE eval-window half, which is recorded
below as an open decision. Everything in group (ii) stays parked.

Each fix was written test-first: the test was added and shown failing against the
current code before the change was made.

## 1. Gate verdicts are tri-state (`07_Forecast.py`)

`_GATE_WORDS_EN` and `_gate_verdict()` follow the page's existing
`_VERDICT_WORDS_EN` idiom. `None` now renders **"not tested"**, and an unrecognised
value maps there too — a gate that cannot be read is not a gate that passed. The
Georgian dictionary gained `"not tested"`, so the badge does not fall back to
English mid-sentence.

The page's own `ui_styles.gate_badge_tri()` was **not** adopted, though it is the
design-system component for this and its docstring already says "None maps to
'never verified', never to a pass". Using it would change the badge's visual form
and bypass `_translate`. Worth revisiting as a design question rather than a bug fix.

**Tests:** `frontend/tests/test_gate_verdict_tri_state.py` (4).

## 2. Interval band colour (`04_Dashboard.py`, `ui_styles.py`)

`color_with_alpha()` in `ui_styles.py` accepts hex (including `#abc` shorthand) and
`rgb()`/`rgba()` in any spacing or case, and **raises** on anything it cannot read.
Substituting a default colour would turn a palette change into a silently wrong
chart. The page's hex-slicing expression is replaced by one call.

**Tests:** `frontend/tests/test_interval_band_colour.py` (6).

## 3. Compare page long-format metrics (`05_Compare.py`, `utils_frontend.py`)

`best_metric_row()` in `utils_frontend.py` returns `(row, reason)` and never raises.
The page loop drops from 18 lines to 5, and the no-`model`-column path is preserved
exactly as it was.

**Skipped rather than pivoted, and this was the decision to make.** The long format
carries `pinball` and `coverage_p10_p90` only — there is no MAE, RMSE, sMAPE or R2
anywhere in it. A pivot could not produce a single column this table ranks by; it
would add a row of blanks implying a comparison that never happened. Runs that
cannot be compared are now **named beneath the table with the reason**, which also
closes the other half of the recorded issue: a missing metrics file used to empty
the table in silence.

**Tests:** `frontend/tests/test_compare_long_format_metrics.py` (7).

## OPEN DECISION — E_QUANTILE's evaluation window

**Not approved, not changed.** E_QUANTILE aborts with the same
`SelectionOnReportOnlyDataError` as B_ML did, but for the opposite reason: its
override at `run_daily_forecast.sh:148` is
`{"eval_start":"2025-01-01","min_train_years":4}`, an evaluation window aimed
deliberately *into* the sealed holdout. Its comment explains why — skill and
coverage need roughly 150 points to mean anything, and the shared benchmark window
is where those points are. That intent collides head-on with the rule that selection
may only happen on `{train, dev}`.

This is a methodology decision, not a typo, and it is left open. The two options:

**Option A — bound selection to DEV, report coverage through the logged release.**
Add an `eval_end` inside DEV so the champion is chosen on selectable data, and obtain
the TEST-window coverage figure separately through `require_test_access`, which is
the sanctioned, logged one-read path. *For:* keeps the seal's meaning intact —
nothing chooses on held-out data. *Against:* DEV alone may not supply the ~150 points
the comment argues coverage needs, so the calibration figure could get noisier, and
the family's evaluation and reporting paths stop being the same code path.

**Option B — open the holdout explicitly with `AI4CM_ALLOW_TEST_READ`.** Have the
script set the variable for this family, which `assert_selection_free` honours for
TEST (but never for LIVE), and accept the logged read. *For:* keeps the ~150-point
benchmark window the comment asks for, and every read is recorded in
`experiments/test_access.log`. *Against:* it makes a selection path read the sealed
holdout as routine rather than once, which is the thing the seal exists to prevent;
the release procedure was designed for a final read, not a daily one.

Until this is settled, C_DL runs ahead of E_QUANTILE so that an abort here costs
only this family.
